## 2. Skill 执行流程

`project-standard-extractor` 是一个文档契约驱动的 Skill source package。它对外只暴露 `skills/project-standard-extractor/SKILL.md`，内部用 6 个 phase contract 编排执行；宿主支持 subagent 时可以拆分执行，不支持时由同一个 agent 按阶段顺序执行。

### 2.1 入口与模式

最小输入是：

```yaml
project_paths:
  - /path/to/project
domain: ""        # 可选，自动推断
output_dir: ""    # 可选，默认 engineering-standards/{domain}/
run_mode: auto    # auto 默认；interactive 可逐步确认
```

当前主路径是 `auto` 模式：只要路径有效且没有全部命中敏感策略，就自动画像、规划 batch、遍历 ready batch、生成规范产物和最终 review summary。`interactive` 保留为高风险或首次探索场景。

### 2.2 6 阶段链路

| 阶段 | 合约文件 | 输入 | 关键动作 | 输出 |
| --- | --- | --- | --- | --- |
| 1. intake-and-scope | `agents/intake-and-scope.md` | `project_paths`、可选 domain / output_dir / run_mode | 校验路径、推断 domain / sub_domain / extraction_mode、识别敏感文件 | `scope_summary`、`run_id` |
| 2. profile-and-batch-planner | `agents/profile-and-batch-planner.md` | `scope_summary`、config refs | 轻量目录扫描，生成项目画像、extraction map、batch plan；auto 模式生成 `ordered_batch_queue` | `{run_id}-project-profile.md`、`{run_id}-extraction-map.md`、`{run_id}-batch-plan.md`、`ordered_batch_queue` |
| 3. facts-and-classification | `agents/facts-and-classification.md` | batch plan、选定 batch、existing standards | 只读取当前 batch 的候选文件；先萃取 facts，再分类为 recommended / forbidden / legacy / pending / conflict | `code_facts`、`classification` |
| 4. generation | `agents/generation.md` | `code_facts`、`classification`、模板、现有规范 | 先写 evidence，再综合生成 Developer Guide，再派生 AI Rules / Review Checklist，最后生成候选索引产物 | `evidence/*`、`standard-{sub_domain}.md`、`ai-rules.md`、`review-checklist.md`、候选索引 |
| 5. review-and-quality-gate | `agents/review-and-quality-gate.md` | 生成的规范、派生规则、evidence、候选索引、existing standards | 7 persona 评审；冲突走 Proposer-Challenger-Arbiter；聚合 quality gate | `review_report`、`quality_gate_decisions[]` |
| 6. merge-coordinator | `agents/merge-coordinator.md` | `quality_gate_decisions[]`、`review_report`、目标目录 | append-only 合并；相似写入 merge suggestions；冲突写入 conflicts；生成最终 review summary | 规范目录文件、`{run_id}-review-summary.md` |

核心执行原则：

- 完整项目 / 多服务 / 未知范围输入先走 profile-first，不直接读完整源码生成规范。
- 正式萃取以 batch 为最小边界，每次只处理一个 batch 的 `candidate_files`。
- 先有 `code_facts`，再有规则分类；分类阶段不得新增事实。
- `evidence/*` 先于标准正文生成，标准正文再派生 `ai-rules.md` 和 `review-checklist.md`。
- 所有写入必须 append-only，不覆盖已有 `active` 或 `draft`。
- 规则正文不写真实绝对路径；路径和正反例留在 `evidence/`。
- `rules-index`、`llms`、`ai-context-pack` 在 Skill 运行中先作为候选产物，不默认覆盖正式入口。
