# APP 客户端性能规范

## 1. 性能目标

APP 性能规范用于约束启动、页面加载、网络、缓存、数据库、行情高频刷新、内存和稳定性。性能优化必须服从架构边界，不得通过绕过 Repository、HSDataCenterKit 或 KMP 共享层获取短期收益。

## 2. 启动性能

强制规则：

1. 启动阶段不得同步执行非必要网络请求。
2. 非关键 SDK 初始化应延迟或异步。
3. 展业地配置、语言、主题等启动必要数据必须有本地兜底。
4. 启动核心容器只负责初始化，不承载页面业务逻辑。
5. 启动耗时增加必须说明原因和影响范围。

推荐规则：

1. 启动任务应分级为 critical、important、lazy。
2. 配置更新可使用本地优先加后台刷新。
3. 日志和监控应覆盖启动关键节点。

## 3. 页面性能

强制规则：

1. 页面首屏数据请求必须明确策略。
2. UI 层不得执行大数据转换。
3. 列表页必须避免主线程重计算。
4. 高频刷新页面必须控制刷新频率。
5. 图片、图表、行情组件必须关注内存释放。

推荐规则：

1. 复杂页面应使用骨架屏或占位状态。
2. 列表页应支持分页、增量刷新和局部刷新。
3. UI State 或 State 应避免持有过大的原始数据。

## 4. 网络性能

强制规则：

1. 网络请求必须走统一网络层或 HSDataCenterKit。
2. 不得在 UI 层重复发起同一请求。
3. 高频请求必须有取消、节流或合并策略。
4. 交易、账户、订单请求必须保留错误日志和追踪信息。

推荐规则：

1. 配置、语言、主题等低频数据使用缓存加版本校验。
2. 首页组合数据应避免串行等待非关键接口。
3. 弱网场景应明确超时、重试和降级策略。

## 5. 缓存与数据库性能

强制规则：

1. 缓存策略必须显式声明。
2. 数据库读写不得阻塞主线程。
3. 大数据量查询必须分页或限制字段。
4. 缓存失效、清理和版本升级必须可控。
5. 高风险数据不得无约束读取旧缓存。

推荐规则：

1. 配置类数据使用 cache first 和后台刷新。
2. 行情类数据使用流式更新和订阅管理。
3. 历史记录、搜索记录等本地数据应限制容量。

## 6. 行情与高频数据性能

强制规则：

1. 高频数据必须有订阅和取消订阅机制。
2. 页面不可见时必须降低刷新或取消订阅。
3. UI 更新必须做合并或节流。
4. 不得在 UI 层处理大量原始行情数据。

推荐规则：

1. Domain 层统一处理行情业务语义。
2. 平台层只负责展示最终 UI State 或 State。
3. 价格、涨跌、颜色语义应保持一致。

## 7. 稳定性规范

强制规则：

1. 交易、账户、订单等高风险模块必须有异常兜底。
2. 关键链路必须有日志。
3. 数据解析失败不得导致页面崩溃。
4. 多展业地配置缺失必须有默认值或阻断策略。
5. Closure、订阅、协程、任务必须关注生命周期释放。

推荐规则：

1. 弱网、无网、超时场景应有明确状态。
2. 非关键能力失败不应阻塞主流程。
3. 崩溃、卡顿、ANR、OOM 应接入监控并追踪模块归因。

## 8. AI 生成规则

AI 生成性能相关代码时必须遵守：

1. 不得通过绕过数据中台优化性能。
2. 高频请求必须说明刷新、取消和节流策略。
3. 大数据转换不得放在 UI 层。
4. 缓存策略必须明确。
5. 涉及启动性能必须说明是否增加启动任务。
6. 涉及交易、账户、订单必须说明异常兜底和日志。

## 9. Review 检查项

- 是否增加启动耗时。
- 页面首屏策略是否明确。
- 是否存在 UI 层大数据转换。
- 是否存在重复请求。
- 高频刷新是否有节流和取消。
- 缓存策略是否合理。
- 数据库读写是否避开主线程。
- 高风险模块是否有日志和异常兜底。
